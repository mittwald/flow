# Best Practices

- Setze ein CoachMark nur für einen Hinweis ein, um den der Nutzer nicht gebeten
  hat. Alles, was er selbst abruft, gehört in ein
  [ContextualHelp](/components/overlays/contextual-help).
- Zeige höchstens ein CoachMark pro Seite. Mehrere gleichzeitig konkurrieren um
  dieselbe Aufmerksamkeit und heben sich gegenseitig auf.
- Halte den Inhalt auf einen Gedanken: was neu ist und was der Nutzer davon hat.
- Blende es dauerhaft aus, sobald es bestätigt wurde. Ein Hinweis, der bei jedem
  Aufruf wiederkommt, wird zur Störung.
- Verlasse dich nicht darauf, dass der Hinweis gelesen wird. Was unerlässlich
  ist, gehört in die Oberfläche selbst.
- Rendere ein CoachMark in einer mStudio-Extension über die `anchor`-Property.
  Eine Referenz erreicht den Host nicht, eine id schon.

# Anker

Ein CoachMark zeigt auf ein Element, nicht auf die Seite. Es gibt keinen
Trigger, denn niemand öffnet es – stattdessen bekommt es den Anker auf einem von
zwei Wegen:

- **`anchorRef`** – die Referenz auf das Element. Der Normalfall in einer
  React-Anwendung.
- **`anchor`** – die `id` des Elements, nachgeschlagen beim Öffnen. Nutze sie,
  wo sich keine Referenz teilen lässt: Eine mStudio-Extension rendert in einem
  anderen Kontext als der Host, eine Ref kommt dort nie an, eine id schon.

Schreibe das CoachMark **direkt hinter das Element, auf das es zeigt**. Es wird
dort gerendert, wo es steht, und folgt dem Anker damit auch in der
Vorlesereihenfolge. Zusätzlich verweist der Anker per `aria-details` darauf.

Weil es an seiner Stelle im Dokument bleibt, erbt es seine Umgebung. Platz
braucht es keinen – es ist absolut positioniert –, aber ein Vorfahre mit
`overflow: hidden` oder ein eigener Stacking Context kann es abschneiden.

# Verhalten

Ein CoachMark sperrt die Seite nicht. Scrollen funktioniert, der Fokus bleibt,
wo er war, und der Hinweis wandert beim Scrollen mit seinem Anker mit. Damit
unterscheidet es sich bewusst von einem Overlay, das eine Entscheidung erzwingt.

Angekündigt wird es nicht. Wer mit einem Screenreader arbeitet, erfährt davon
beim Lesen – deshalb die Empfehlung oben, es direkt hinter seinen Anker zu
setzen.

# Schließen

Das CoachMark bringt seinen eigenen Button mit, beschriftet mit einem
übersetzten „Verstanden". Mit `dismissLabel` gibst du ihm einen eigenen Text,
mit `hideDismissButton` nimmst du ihn weg – etwa, wenn du das Schließen an eine
andere Aktion hängst. Escape schließt es ebenfalls.
