# Best Practices

- Setze ein CoachMark nur für einen Hinweis ein, um den niemand gebeten hat.
  Alles, was Nutzende selbst aufrufen, gehört in ein
  [ContextualHelp](/components/overlays/contextual-help).
- Zeige höchstens ein CoachMark pro Seite. Mehrere konkurrieren um dieselbe
  Aufmerksamkeit und heben sich gegenseitig auf.
- Beschränke den Inhalt auf einen Gedanken. Sag, was neu ist und was es bringt.
- Blende ein bestätigtes CoachMark dauerhaft aus. Merke dir die Bestätigung in
  `onOpenChange` und setze `isDefaultOpen` beim nächsten Aufruf entsprechend –
  ein Hinweis, der jedes Mal wiederkommt, wird zur Störung.
- Verlasse dich nicht darauf, dass der Hinweis gelesen wird. Was unerlässlich
  ist, gehört in die Oberfläche selbst.
- Schreibe das CoachMark direkt hinter sein Ankerelement. Angekündigt wird es
  nicht, gefunden wird es über die Vorlesereihenfolge.
- Nutze in einer mStudio-Extension die `anchor`-Property. Eine Referenz erreicht
  den Host nicht, eine id schon.

## CoachMark vs. ContextualHelp

Beide zeigen einen kurzen Hinweis neben einem Bedienelement. Der Unterschied
liegt darin, wer ihn öffnet – und was das für die restliche Seite bedeutet. Ein
ContextualHelp ist ein Dialog: Es sperrt das Scrollen und zieht den Fokus zu
sich. Ein CoachMark lässt die Seite unberührt.

<DoAndDont>
  <Plain heading="Verwende ein CoachMark, um z. B. ...">
    - auf eine neue oder verschobene Funktion hinzuweisen.
    - eine Funktion zu zeigen, die leicht zu übersehen ist.
    - einen Hinweis zu geben, ohne die Arbeit zu unterbrechen.

  </Plain>

  <Plain heading="Verwende ein ContextualHelp, um z. B. ...">
    - einen Fachbegriff zu erklären, wenn jemand danach fragt.
    - Hintergrund zu einem Formularfeld anzubieten.
    - eine Einstellung mit ihren Folgen zu beschreiben.

  </Plain>
</DoAndDont>

# Anker

Ein CoachMark zeigt auf ein Element, nicht auf die Seite. Einen Trigger gibt es
nicht, denn niemand öffnet es – stattdessen bekommt es den Anker auf einem von
zwei Wegen:

- `anchorRef` ist die Referenz auf das Element. Das ist der Normalfall in einer
  React-Anwendung.
- `anchor` ist die `id` des Elements, nachgeschlagen beim Öffnen. Sie hilft
  dort, wo sich keine Referenz teilen lässt: Eine mStudio-Extension rendert in
  einem anderen Kontext als der Host, eine Referenz kommt dort nie an, eine id
  schon.

Das CoachMark wird dort gerendert, wo es steht. Hinter seinem Ankerelement
notiert, folgt es diesem auch in der Vorlesereihenfolge; zusätzlich verweist der
Anker per `aria-details` darauf. Angekündigt wird es nicht – wer mit einem
Screenreader arbeitet, erfährt beim Lesen davon.

Weil es an seiner Stelle im Dokument bleibt, erbt es seine Umgebung. Platz
braucht es keinen, da es absolut positioniert ist. Ein Vorfahre mit
`overflow: hidden` oder ein eigener Stacking Context kann es allerdings
abschneiden.

Beim Scrollen wandert das CoachMark mit seinem Anker mit und bleibt geöffnet.

# Schließen

Das CoachMark bringt seinen eigenen Button mit, beschriftet mit einem
übersetzten „Verstanden". Mit `dismissLabel` bekommt er einen eigenen Text, mit
`hideDismissButton` entfällt er – etwa, wenn das Schließen an einer anderen
Aktion hängt. Escape schließt das CoachMark ebenfalls.

`onOpenChange` meldet jede Änderung, unabhängig davon, welcher Weg sie ausgelöst
hat. Das ist der Platz, um die Bestätigung zu speichern; beim nächsten Aufruf
unterdrückt `isDefaultOpen={false}` den Hinweis dann.
