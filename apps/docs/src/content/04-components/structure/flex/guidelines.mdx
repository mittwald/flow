# Grundlagen

Flex wurde eingeführt, um eine flexible Anordnung von Inhalten auf Basis der
CSS-Flexbox zu ermöglichen. So bleibt unser Designsystem offen genug, um auch
spezifische, schwer zu standardisierende Anforderungen und Layouts abzubilden.

## Best Practices

Achte bei der Verwendung von Flex darauf, dass ...

- sie nicht für Layouts verwendet wird, die einem festen UI-Pattern folgen und
  sich mit [Combine](/04-components/structure/combine/overview) umsetzen lassen.
- sie gezielt für Sonderfälle genutzt wird – in den meisten Fällen bietet unser
  Designsystem bereits eine passende Lösung.

## Flex vs. Combine

Flex ist das freie Werkzeug,
[Combine](/04-components/structure/combine/overview) das fertige Pattern. Prüfe
deshalb zuerst, ob die gewünschte Anordnung schon als Kombination in Combine
existiert – dann bleibt sie auch bei geändertem Inhalt und über alle Breakpoints
korrekt.

<DoAndDont>
  <Plain heading="Verwende Flex, um ...">
    - individuelle Layouts zu gestalten, die keinem festen UI Pattern folgen.
    - bewusst vom Standard des Designsystems abzuweichen.

  </Plain>

  <Plain heading="Verwende Combine, um ...">
    - vorab definierte Components miteinander zu kombinieren und automatisch anzuordnen.
    - wiederkehrende UI Patterns konsistent umzusetzen.

  </Plain>
</DoAndDont>

Die vollständige Abgrenzung inklusive
[ColumnLayout](/04-components/structure/column-layout/overview) steht in den
[Combine Guidelines](/04-components/structure/combine/guidelines#grundlagen-combine-vs-flex-vs-columnlayout).
