# Grundlagen

## Best Practices

- Halte Labels kurz (1-3 Wörter) und prägnant.
- Stelle sicher, dass das Label jederzeit vollständig sichtbar ist.
- Verwende eine einfache Sprache.

## Verwendung

Verwende ein Label, um ...

- die Eingabeanforderungen an Components innerhalb von Formularen (z. B.
  [TextField](/04-components/form-controls/text-field/overview),
  [NumberField](/04-components/form-controls/number-field/overview),
  [RadioGroup](/04-components/form-controls/radio-group/overview), ...) zu
  erläutern.
- eine Information in Kontext zu setzen, z. B. beim
  [LabeledValue](/04-components/content/labeled-value/overview).

# Writing Guidelines

Das Label sollte ...

- kurz (1-3 Wörter), prägnant und leicht verständlich sein.
- jederzeit vollständig sichtbar und einzeilig sein. Bei sehr schmalen
  Bildschirmen kann es passieren, dass es zweizeilig wird.
- keine Verben wie „eingeben“, „hinzufügen“ oder „wählen“ enthalten.
- keine Formatierungshinweise geben. Nutze dafür z. B. die FieldDescription im
  [TextField](/04-components/form-controls/text-field/overview).
- keinen Doppelpunkt am Ende haben.

# States

Das Label hat 2 verschiedene States: **Default** und **Disabled**.

<LiveCodeEditor example="states" editorCollapsed row />

**Disabled:** Das Label wird häufig zur Beschreibung komplexerer Components
verwendet. Daher übernimmt es automatisch den State, den die höhere Component
hat. Ist zum Beispiel ein
[TextField](/04-components/form-controls/text-field/overview) oder
[NumberField](/04-components/form-controls/number-field/overview) gerade
**disabled**, nimmt das Label den gleichen State an.
